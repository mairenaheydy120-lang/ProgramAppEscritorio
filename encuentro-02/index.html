Vivencia

El viernes, en el agroservicio de doña Martha, se fue la luz a media mañana. Cuando volvió, AgroStock v1 abrió vacío: todo lo registrado estaba en memoria. El lunes, su hijo quiso cargar la lista de 500 productos que le envió el distribuidor y la ventana se quedó blanca, con el mensaje «No responde», durante casi un minuto.

  1. ¿Dónde deberían guardarse los datos para que sobrevivan a un apagón?
  2. Si dos personas registran ventas a la vez, ¿qué problemas pueden aparecer?
  3. ¿Por qué crees que la ventana «no responde» mientras se importa la lista?
  4. ¿Qué haría un buen programa mientras realiza una tarea larga? Piensa en las aplicaciones que usas en el celular.
Lo que esperamos aprender: guardar y consultar datos en una base relacional desde C#, y ejecutar tareas largas en segundo plano de forma segura y cancelable.

Unidad II · 1. Introducción a la programación con bases de datos

Una base de datos relacional organiza la información en tablas formadas por filas (registros) y columnas (campos). Cada tabla tiene una clave primaria que identifica cada fila, y las relaciones entre tablas se expresan con claves foráneas. El sistema gestor (SGBD) garantiza la integridad de los datos mediante restricciones.

En este curso usamos SQLite: un motor relacional que guarda toda la base en un único archivo (agrostock.db) y no requiere instalar un servidor, lo que lo hace ideal para aplicaciones de escritorio y equipos con recursos limitados. Los conceptos y el código son equivalentes para MySQL o SQL Server: solo cambia el proveedor (MySqlConnection, SqlConnection).

TablaCampos principalesRelación
categoriasid (PK), nombre (UNIQUE)Una categoría tiene muchos productos
productosid (PK), codigo (UNIQUE), nombre, categoria_id (FK), precio (CHECK > 0), existencia, vencimientoPertenece a una categoría
movimientosid (PK), producto_id (FK), tipo (ENTRADA/SALIDA), cantidad, fechaMuchos movimientos por producto

Arquitectura: la aplicación no habla directamente con el archivo. Usa un proveedor ADO.NET (Microsoft.Data.Sqlite) que traduce las llamadas de C# en instrucciones para el motor.

Unidad II · 2. El lenguaje SQL

SQL (Structured Query Language) es el lenguaje estándar de las bases relacionales. Se divide en DDL (definición: CREATE, ALTER, DROP) y DML (manipulación: INSERT, SELECT, UPDATE, DELETE).

SQL
CREATE TABLE productos (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    codigo        TEXT    NOT NULL UNIQUE,
    nombre        TEXT    NOT NULL,
    categoria_id  INTEGER NOT NULL REFERENCES categorias(id),
    precio        REAL    NOT NULL CHECK (precio > 0),
    existencia    INTEGER NOT NULL DEFAULT 0 CHECK (existencia >= 0),
    vencimiento   TEXT    NULL
);
Operación CRUDSentencia SQLEjemplo
CreateINSERTINSERT INTO productos (codigo, nombre, categoria_id, precio) VALUES ('FER-004','Sulfato',1,980);
ReadSELECTSELECT codigo, nombre FROM productos WHERE existencia < 10 ORDER BY nombre;
UpdateUPDATEUPDATE productos SET precio = precio * 1.05 WHERE categoria_id = 1;
DeleteDELETEDELETE FROM productos WHERE codigo = 'HER-005';
SQL
-- JOIN: nombre de la categoría junto al producto
SELECT p.codigo, p.nombre, c.nombre AS categoria
FROM productos p JOIN categorias c ON c.id = p.categoria_id;

-- GROUP BY: valor del inventario por categoría
SELECT c.nombre, COUNT(*) AS productos, SUM(p.precio * p.existencia) AS valor
FROM productos p JOIN categorias c ON c.id = p.categoria_id
GROUP BY c.nombre ORDER BY valor DESC;
Cuidado: un UPDATE o DELETE sin WHERE afecta a todas las filas de la tabla. Escribe primero el SELECT con el mismo WHERE para ver qué filas cambiarán.
Unidad II · 3. Clases para la gestión de bases de datos

ADO.NET define un conjunto de clases comunes a todos los proveedores. Con Microsoft.Data.Sqlite se llaman así:

ClaseResponsabilidad
SqliteConnectionAbre y cierra la conexión con el archivo de la base (cadena de conexión).
SqliteCommandContiene la sentencia SQL y sus parámetros. ExecuteReader (SELECT), ExecuteNonQuery (INSERT/UPDATE/DELETE), ExecuteScalar (un valor).
SqliteDataReaderRecorre las filas del resultado, hacia adelante y de solo lectura.
SqliteTransactionAgrupa varias operaciones: se confirman todas (Commit) o ninguna (Rollback).
C#
public List<Producto> Listar(string filtro = "")
{
    using var cn = Db.Abrir();                 // using: cierra la conexión siempre
    using var cmd = cn.CreateCommand();
    cmd.CommandText = SelectBase + " WHERE p.nombre LIKE $f OR p.codigo LIKE $f ORDER BY p.nombre";
    cmd.Parameters.AddWithValue("$f", $"%{filtro}%");   // parámetro, nunca concatenar

    var lista = new List<Producto>();
    using var rd = cmd.ExecuteReader();
    while (rd.Read())
        lista.Add(new Producto { Id = rd.GetInt32(0), Codigo = rd.GetString(1), Nombre = rd.GetString(2) /* … */ });
    return lista;
}

Inyección SQL: si se concatena lo que escribe el usuario ("... WHERE nombre = '" + txtBuscar.Text + "'"), alguien puede escribir ' OR 1=1 -- y alterar la consulta. Los parámetros ($f) envían el valor por separado y el motor nunca lo interpreta como código SQL.

Patrón Repositorio: todo el SQL vive en una clase (ProductoRepository) y los formularios solo llaman a sus métodos (Listar, Insertar, Actualizar, Eliminar). Así la interfaz no depende del motor de base de datos.

Unidad II · 4. Controles de acceso a bases de datos y CRUD

Windows Forms enlaza datos a controles mediante la propiedad DataSource. BindingSource actúa como intermediario: conoce el elemento actual (Current), permite filtrar y notifica cambios.

C#
fuente.DataSource = repo.Listar(txtBuscar.Text);   // BindingSource
dgv.DataSource = fuente;                            // DataGridView

cboCategoria.DataSource = repo.Categorias();
cboCategoria.DisplayMember = "Nombre";   // lo que se ve
cboCategoria.ValueMember = "Id";         // lo que se guarda (SelectedValue)
C#
private void Nuevo()
{
    var p = new Producto();
    using var dlg = new FrmProducto(p, repo.Categorias());
    if (dlg.ShowDialog(this) != DialogResult.OK) return;
    try { repo.Insertar(p); Cargar(); }
    catch (SqliteException ex) when (ex.SqliteErrorCode == 19)   // SQLITE_CONSTRAINT
    {
        MessageBox.Show(this, $"El código {p.Codigo} ya existe.", "No se guardó");
    }
}
Unidad III · 5. Introducción a la programación concurrente

Un proceso es un programa en ejecución con su propia memoria. Un hilo (thread) es una secuencia de instrucciones dentro de un proceso; un proceso puede tener varios hilos que comparten la misma memoria. La programación concurrente consiste en organizar varias tareas que progresan al mismo tiempo, ya sea en paralelo (varios núcleos) o intercalándose.

Las aplicaciones Windows Forms tienen un único hilo de interfaz (UI thread) que procesa los eventos y dibuja la ventana. Si un manejador de eventos tarda 30 segundos, durante ese tiempo la ventana no puede redibujarse ni responder: Windows la marca como «No responde». La solución es mover el trabajo pesado a otro hilo y devolver solo los resultados a la interfaz.

Unidad III · 6. Clases para trabajar con hilos
Clase / técnicaCuándo usarla
ThreadControl directo de un hilo (nombre, prioridad, IsBackground). Útil para aprender los estados; costoso crear muchos.
ThreadPoolConjunto de hilos reutilizables administrado por .NET.
Task + Task.RunOpción recomendada: ejecuta trabajo en el ThreadPool y se puede esperar con await.
async / awaitEspera una tarea sin bloquear el hilo de la interfaz; el código continúa en la UI al terminar.
BackgroundWorkerComponente histórico de Windows Forms (eventos DoWork, ProgressChanged, RunWorkerCompleted).
IProgress<T> / Progress<T>Reporta avance desde el hilo de trabajo; el manejador se ejecuta en el hilo de la UI.
C#
btnSegundoPlano.Click += async (_, _) =>
{
    cts = new CancellationTokenSource();
    var progreso = new Progress<int>(pct => barra.Value = pct);   // corre en la UI
    try
    {
        await Task.Run(() => Importar(ruta, progreso, cts.Token)); // corre en el ThreadPool
        lbl.Text = "Importación terminada";
    }
    catch (OperationCanceledException) { lbl.Text = "Cancelada"; }
};

Unidad III · 8. Mecanismos de sincronización

Cuando dos hilos modifican el mismo dato sin coordinación ocurre una condición de carrera: la operación contador++ en realidad es leer, sumar y escribir, y los hilos pueden intercalarse perdiendo incrementos.

C#
object candado = new();
lock (candado) { contador++; }              // sección crítica: un hilo a la vez
Interlocked.Increment(ref contador2);       // operación atómica

using var semaforo = new SemaphoreSlim(2);  // máximo 2 tareas simultáneas
await semaforo.WaitAsync();
try { /* descarga */ } finally { semaforo.Release(); }

Regla de oro de Windows Forms: solo el hilo de la interfaz puede tocar los controles. Desde otro hilo se usa IProgress<T>, Control.Invoke o se devuelve el resultado y se asigna después del await. Violar esta regla produce la excepción «Operación no válida a través de subprocesos».

Unidad III · 9. Detención controlada de hilos

Un hilo nunca debe detenerse a la fuerza (Thread.Abort está obsoleto y no funciona en .NET moderno): puede dejar archivos abiertos o datos a medias. La detención controlada es cooperativa: la interfaz solicita la cancelación con CancellationTokenSource.Cancel() y el hilo revisa el token periódicamente, libera recursos y termina.

C#
using var tx = cn.BeginTransaction();
for (int i = 0; i < lineas.Length; i++)
{
    if (token.IsCancellationRequested)
    {
        tx.Rollback();                       // nada queda a medias
        token.ThrowIfCancellationRequested();
    }
    repo.Insertar(Parsear(lineas[i]), cn, tx);
    progreso?.Report((i + 1) * 100 / lineas.Length);
}
tx.Commit();

Síntesis
  • Los datos viven en la base, no en la memoria: sobreviven al cierre y a los apagones.
  • Toda consulta con datos del usuario se parametriza.
  • El hilo de la interfaz solo dibuja y responde; el trabajo pesado va a otro hilo o tarea.
  • La sincronización protege los datos compartidos y la cancelación cooperativa detiene sin dejar datos a medias.
