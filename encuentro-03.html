Uso de ORM y generación de reportes

1. ¿Qué es un ORM?

Un ORM (Object-Relational Mapper, mapeador objeto-relacional) traduce automáticamente entre los objetos del programa y las tablas de la base de datos. El programador trabaja con clases y colecciones; el ORM genera el SQL, abre las conexiones y convierte las filas en objetos. En .NET, el ORM oficial es Entity Framework Core (EF Core).

Mundo orientado a objetosMundo relacional
Clase ProductoTabla productos
Propiedad NombreColumna Nombre
Objeto (instancia)Fila
Referencia Producto.CategoriaClave foránea CategoriaId
HasOne(...).WithMany()Relación 1:N entre categorias y productos
  • Ventajas: menos código repetitivo, consultas verificadas por el compilador (LINQ), independencia del motor (SQLite, SQL Server, MySQL, PostgreSQL), protección contra inyección SQL.
  • Límites: menos control sobre el SQL generado; consultas muy complejas pueden ser menos eficientes; hay que entender qué consulta se ejecuta y cuándo.

Ejemplo aplicado — AgroStock: en v2 había un SQL distinto para listar, insertar, actualizar y eliminar. En v3 el repositorio trabaja con objetos Producto y EF Core escribe el SQL.

2. Entity Framework Core: entidades y DbContext

En AgroStock v3 el modelo de datos se describe con clases: tres entidades (Producto, Categoria y Movimiento) y un DbContext (AgroStockContext) que reemplaza al script agrostock.sql del Encuentro 2.

public class Producto
{
    public int Id { get; set; }                                 // clave primaria (por convención)
    public string Codigo { get; set; } = "";
    public string Nombre { get; set; } = "";
    public int CategoriaId { get; set; }                        // clave foránea
    public Categoria? Categoria { get; set; }                   // propiedad de navegación
    public decimal Precio { get; set; }
    public int Existencia { get; set; }
    public DateTime? Vencimiento { get; set; }
    public string CategoriaNombre => Categoria?.Nombre ?? "";   // solo lectura, para la cuadrícula
}

public class Categoria { public int Id { get; set; } public string Nombre { get; set; } = ""; }

public class Movimiento
{
    public int Id { get; set; }
    public int ProductoId { get; set; }
    public Producto? Producto { get; set; }
    public string Tipo { get; set; } = "ENTRADA";       // ENTRADA o SALIDA
    public int Cantidad { get; set; }
    public DateTime Fecha { get; set; } = DateTime.Today;
}
public class AgroStockContext : DbContext
{
    public DbSet<Categoria> Categorias => Set<Categoria>();
    public DbSet<Producto> Productos => Set<Producto>();
    public DbSet<Movimiento> Movimientos => Set<Movimiento>();

    protected override void OnConfiguring(DbContextOptionsBuilder options)
        => options.UseSqlite($"Data Source={Ruta}");          // archivo agrostock.db

    protected override void OnModelCreating(ModelBuilder mb)
    {
        mb.Entity<Producto>(e =>
        {
            e.ToTable("productos", t => t.HasCheckConstraint("ck_precio", "precio > 0"));
            e.Property(p => p.Codigo).IsRequired();
            e.HasIndex(p => p.Codigo).IsUnique();             // código sin repetir
            e.HasOne(p => p.Categoria).WithMany()
             .HasForeignKey(p => p.CategoriaId).OnDelete(DeleteBehavior.Restrict);
        });

        mb.Entity<Categoria>().HasData(                       // datos iniciales
            new Categoria { Id = 1, Nombre = "Fertilizantes" },
            new Categoria { Id = 2, Nombre = "Semillas" });   // ... y el resto
    }
}

public static class Db
{
    public static void Inicializar()
    {
        using var ctx = new AgroStockContext();
        ctx.Database.EnsureCreated();          // crea agrostock.db, tablas, restricciones y datos iniciales
    }
}

El DbContext representa una sesión de trabajo con la base: rastrea los objetos que se agregan o modifican y, al llamar a SaveChanges(), genera y ejecuta los INSERT, UPDATE y DELETE necesarios dentro de una transacción. Database.EnsureCreated() crea la base y las tablas si no existen; en proyectos mayores se usan migraciones (dotnet ef migrations add).

Importante: EnsureCreated no actualiza una base que ya tiene tablas. Si cambia el modelo, borre agrostock.db de la carpeta bin\Debug\net8.0-windows y ejecute de nuevo. La base se crea sola la primera vez, con las 4 categorías, los 14 productos y los 6 movimientos iniciales.

3. CRUD con LINQ sin escribir SQL

OperaciónEF CoreSQL generado (aprox.)

Createctx.Productos.Add(p); ctx.SaveChanges();INSERT INTO productos …
Updatectx.Productos.Update(p); ctx.SaveChanges();UPDATE productos SET … WHERE Id = …
Deletectx.Productos.Remove(p); ctx.SaveChanges();DELETE FROM productos WHERE Id = …

ProductoRepository conserva los mismos métodos del Encuentro 2, pero cada uno abre un AgroStockContext con using y no contiene ninguna sentencia SQL:

public List<Producto> Listar(string filtro = "")
{
    using var ctx = new AgroStockContext();
    return ctx.Productos
        .Include(p => p.Categoria)                                    // JOIN con categorias
        .Where(p => EF.Functions.Like(p.Nombre, $"%{filtro}%")
                 || EF.Functions.Like(p.Codigo, $"%{filtro}%"))       // LIKE con parámetro
        .OrderBy(p => p.Nombre)
        .ToList();
}

public void RegistrarMovimiento(int productoId, string tipo, int cantidad)
{
    using var ctx = new AgroStockContext();
    var p = ctx.Productos.Find(productoId) ?? throw new InvalidOperationException("Producto no encontrado.");
    if (tipo == "SALIDA" && p.Existencia < cantidad)
        throw new InvalidOperationException("Existencia insuficiente: no se registró nada.");

    p.Existencia += tipo == "ENTRADA" ? cantidad : -cantidad;
    ctx.Movimientos.Add(new Movimiento { ProductoId = productoId, Tipo = tipo,
                                         Cantidad = cantidad, Fecha = DateTime.Today });
    ctx.SaveChanges();   // una sola transacción para ambos cambios
}

Ejecución diferida. Una consulta LINQ no va a la base hasta que se enumera (ToList, First, Count, foreach). Construya la consulta completa antes de materializarla.

InsertarVarios inserta muchos productos con un solo SaveChanges (una transacción) y devuelve los códigos que ya existían en lugar de fallar; Limpio() copia el producto sin su objeto Categoria para que EF no intente actualizar también esa tabla.

Errores del ORM. Cuando la base rechaza un cambio, EF Core lanza una DbUpdateException; la causa real está en ex.InnerException (la SqliteException). FrmPrincipal la evalúa con when para avisar de un código repetido o de un producto con movimientos sin cerrar el programa:

catch (DbUpdateException ex) when (ex.InnerException is SqliteException { SqliteExtendedErrorCode: 2067 })
{   // UNIQUE: el código ya existe
    MessageBox.Show(this, $"El código {codigo} ya existe.", "No se guardó");
}
catch (DbUpdateException ex) when (ex.InnerException is SqliteException { SqliteErrorCode: 19 } fk
                                   && fk.Message.Contains("FOREIGN KEY"))
{   // el producto tiene movimientos registrados
    MessageBox.Show(this, "No se puede eliminar: el producto tiene movimientos registrados.", "No se eliminó");
}

Ejemplo aplicado — AgroStock: si doña Martha intenta registrar dos veces el código FER-001 o borrar un producto con movimientos, la base lo rechaza y AgroStock explica el motivo sin cerrarse.

4. Generación de reportes

Un reporte presenta datos de la base de forma organizada para tomar decisiones. Su estructura clásica: encabezado (título, fecha, filtros), detalle (filas), agrupaciones y totales, y pie (numeración). El programa pide exportar a PDF o Excel; usamos dos bibliotecas libres para uso académico: QuestPDF (PDF con API fluida en C#) y ClosedXML (Excel sin necesidad de tener Office instalado).

ReporteService recibe la lista de productos ya leída y la ruta que eligió el usuario. El PDF usa A4 horizontal, resalta las existencias menores que 10 y muestra en el pie el total y la numeración de páginas:

Document.Create(doc => doc.Page(page =>
{
    page.Size(PageSizes.A4.Landscape());
    page.Header().Column(col =>
    {
        col.Item().Text("AgroStock - Reporte de inventario").FontSize(18).Bold();
        col.Item().Text($"Generado: {DateTime.Now:dd/MM/yyyy HH:mm}").FontSize(9);
    });
    page.Content().Table(tabla =>
    {
        // ... columnas y encabezado de la tabla ...
        foreach (var p in productos)
        {
            var fondo = p.Existencia < 10 ? Colors.Red.Lighten4 : Colors.White;    // existencia baja resaltada
            Celda(tabla, p.Codigo, fondo);
            Celda(tabla, p.Nombre, fondo);
            Celda(tabla, p.Precio.ToString("N2"), fondo);   // ... y las demás columnas
        }
    });
    page.Footer().Row(r =>
    {
        r.RelativeItem().Text($"Productos: {productos.Count}   |   Valor del inventario: C$ {valorTotal:N2}");
        r.RelativeItem().AlignRight().Text(t =>
        { t.Span("Página "); t.CurrentPageNumber(); t.Span(" de "); t.TotalPages(); });
    });
})).GeneratePdf(ruta);

El libro de Excel escribe el valor de cada fila y el total como fórmulas, de modo que se recalculen si el usuario cambia un dato:

using var libro = new XLWorkbook();
var hoja = libro.Worksheets.Add("Inventario");
// ... encabezados con estilo (negrita, fondo verde oscuro) ...
int fila = 2;
foreach (var p in productos)
{
    hoja.Cell(fila, 1).Value = p.Codigo;
    hoja.Cell(fila, 4).Value = p.Precio;
    hoja.Cell(fila, 5).Value = p.Existencia;
    hoja.Cell(fila, 7).FormulaA1 = $"D{fila}*E{fila}";          // valor = precio por existencia
    fila++;
}
hoja.Cell(fila, 7).FormulaA1 = $"SUM(G2:G{fila - 1})";            // total como fórmula
hoja.Range(2, 4, fila, 4).Style.NumberFormat.Format = "#,##0.00";
hoja.SheetView.FreezeRows(1);
libro.SaveAs(ruta);
Buenas prácticas: declarar la licencia de QuestPDF (QuestPDF.Settings.License = LicenseType.Community) en el constructor estático, pedir la ruta con SaveFileDialog (Unidad I), capturar IOException cuando el archivo está abierto en otro programa, usar fórmulas en Excel en lugar de valores calculados y mantener el reporte en una clase de servicio que no conoce los formularios.

Ejemplo aplicado — AgroStock: el reporte del lunes que el hijo de doña Martha copiaba a mano ahora se genera con un clic, con las existencias bajas resaltadas y el valor del inventario sumado.

Consumo de servicios web

5. Servicios web y HTTP

Un servicio web es una aplicación que ofrece datos o funciones a otras aplicaciones a través de la red usando el protocolo HTTP. En el estilo REST, cada recurso tiene una URL y se opera con métodos HTTP; las respuestas suelen venir en JSON (y en servicios más antiguos, en XML).

ElementoEjemplo
MétodoGET (leer), POST (crear), PUT (reemplazar), DELETE (eliminar); AgroStock usa GET
URLhttps://api.mockaroo.com/api/generate.json?schema=agrostock_productos&count=20&array=true
Código de estado200 OK · 401 Clave incorrecta · 404 No encontrado (el schema no existe) · 500 Error del servidor
EncabezadosX-API-Key: (su clave de API)
Cuerpo (JSON)[ { "codigo": "SEM-4821", "nombre": "Semilla de arroz (libra)", "categoria": "Semillas", "precio": 85.50, "existencia": 40, "vencimiento": "2027-05-01" } ]

Ejemplo aplicado — AgroStock: pedir 20 productos de prueba es una petición GET a una URL; el servicio responde con una lista JSON.

La configuración del servicio (dirección, clave y nombre del schema) vive en appsettings.json, que se copia junto al ejecutable; MockarooClient la lee al crearse:

{
    "Mockaroo": {
      "BaseUrl": "https://api.mockaroo.com/api/generate.json",
      "ApiKey": "<su clave de API>",
      "Schema": "agrostock_productos"
    }
}
public class ProductoMockaroo
{
    [JsonPropertyName("codigo")]      public string Codigo { get; set; } = "";
    [JsonPropertyName("nombre")]      public string Nombre { get; set; } = "";
    [JsonPropertyName("categoria")]   public string Categoria { get; set; } = "";
    [JsonPropertyName("precio")]      public decimal Precio { get; set; }
    [JsonPropertyName("existencia")]  public int Existencia { get; set; }
    [JsonPropertyName("vencimiento")] public string? Vencimiento { get; set; }
}

private static readonly HttpClient Http = new() { Timeout = TimeSpan.FromSeconds(30) };

public List<ProductoMockaroo> ObtenerProductos(int cantidad)
{
    var url = $"{baseUrl}?schema={Uri.EscapeDataString(schema)}&count={cantidad}&array=true";
    using var req = new HttpRequestMessage(HttpMethod.Get, url);
    req.Headers.Add("X-API-Key", apiKey);                 // la clave viaja en un encabezado

    using var resp = Http.Send(req);                      // llamada síncrona: la interfaz espera
    using var flujo = resp.Content.ReadAsStream();
    if (!resp.IsSuccessStatusCode)
    {
        using var lector = new StreamReader(flujo);
        throw new HttpRequestException($"Mockaroo respondió {(int)resp.StatusCode}: {lector.ReadToEnd()}");
    }
    return JsonSerializer.Deserialize<List<ProductoMockaroo>>(flujo) ?? new();   // JSON a objetos
}

MockarooClient.Convertir descarta las filas inválidas (categoría desconocida, código o nombre de menos de 3 caracteres, precio menor o igual que cero, existencia negativa) para contarlas como rechazadas antes de guardar.

Sin hilos, a propósito. Http.Send es una llamada síncrona: mientras llega la respuesta, la ventana no responde un instante (el cursor cambia a espera). En el Encuentro 2 resolvió ese problema con Task.Run e IProgress; combinar ambas ideas es el reto 3. Siempre se deben prever los fallos: sin conexión (HttpRequestException), tiempo agotado (TaskCanceledException), respuesta inesperada (JsonException) y clave faltante (InvalidOperationException).
catch (DbUpdateException ex)
{   // la base rechazó algo: se revirtió toda la importación
    lblEstado.Text = "Se revirtió la importación: " + (ex.InnerException?.Message ?? ex.Message);
}
catch (Exception ex) when (ex is IOException or HttpRequestException or InvalidOperationException
                               or TaskCanceledException or System.Text.Json.JsonException)
{
    lblEstado.Text = "No se pudo completar: " + ex.Message;
}

Ejemplo aplicado — AgroStock: si se cae el Internet de la cooperativa mientras se piden productos, el programa muestra «No se pudo completar» y sigue funcionando.

7. Estudio de caso: productos de prueba con Mockaroo

Probar un inventario con 14 productos no basta: doña Martha necesita ver cómo se comporta AgroStock con cientos. Mockaroo es un servicio web que genera datos de prueba realistas según un schema; el schema agrostock_productos tiene seis campos (codigo, nombre, categoria, precio, existencia y vencimiento) con los mismos nombres que las propiedades de ProductoMockaroo.

FrmImportar ofrece dos orígenes: el archivo productos_importar.csv y el botón «Obtener de Mockaroo» (de 1 a 1000 productos). Ambos pasan por el mismo método Ejecutar, que guarda con InsertarVarios en una sola transacción: si la base rechaza algo se revierte toda la importación. Al terminar informa cuántos productos entraron, cuántas filas eran inválidas y cuántos códigos estaban repetidos; importar el mismo CSV dos veces no falla, la segunda vez informa los repetidos.

  • Analice el servicio antes de usarlo: documentación, límites del plan gratuito y términos de uso.
  • No publique su clave: appsettings.json contiene un secreto. Si sube el proyecto a un repositorio público, quítela o cámbiela; en la entrega use la clave que indique su docente.
  • Otros casos posibles: consultar el tipo de cambio oficial que publica el Banco Central de Nicaragua (BCN), si ofrece un servicio consultable, o el clima para planificar la aplicación de fertilizantes.

Ejemplo aplicado — AgroStock: con un clic, 500 productos de prueba entran al inventario; si algunos vienen con precio cero, se descartan y AgroStock cuenta cuántos fueron.

Práctica de programación

Resuelva de forma individual los siguientes ejercicios. Las 5 consultas LINQ son obligatorias (tarea 2 de la BOA 3); los retos de programación se integran en AgroStock v3. Con la base recién creada por AgroStockContext (datos iniciales sin modificar), los resultados esperados son los indicados entre paréntesis.

Nivel 1 – Básico

  1. Devuelva los productos de la categoría «Semillas» ordenados por nombre (3 productos).
  2. Cuente los productos con existencia menor que 10 (7 productos).
  3. Obtenga el producto de mayor precio con OrderByDescending + FirstOrDefault («Bomba de mochila (20 L)», C$ 1,450.00).
  4. Reto de programación 1: agregue un ComboBox de categoría en la barra de la ventana principal y filtre la lista con LINQ: .Where(p => p.CategoriaId == id).

Nivel 2 – Intermedio

  1. Calcule el valor total del inventario (C$ 86,381.00).
  2. Agrupe por categoría y devuelva cantidad de productos y valor con GroupBy (Fertilizantes 3 · C$ 56,880.00; Semillas 3 · C$ 10,651.00; Herbicidas 5 · C$ 11,600.00; Herramientas 3 · C$ 7,250.00).
  3. Reto de programación 2: haga que los reportes PDF y Excel usen la lista filtrada por la búsqueda actual (o por la categoría elegida) en lugar de todos los productos.

Nivel 3 – Avanzado (opcional)

  1. Reto de programación 3: ejecute ObtenerProductos dentro de Task.Run con await para que la ventana no se congele durante la llamada a Mockaroo.
  2. Reto de programación 4: mueva la clave de Mockaroo a una variable de entorno y léala con Environment.GetEnvironmentVariable.

Entrega

Suba al aula virtual el código de las 5 consultas LINQ con sus resultados y el reporte de una categoría (tarea «Ejercitación E3»), el proyecto AgroStock v3 comprimido sin las carpetas bin, obj ni .vs (con la clave de API que indique su docente), el manual de usuario en PDF con el enlace del video, y complete el formulario de autoevaluación. Si usó ejemplos o IA, indíquelo en el README.

    Glosario del encuentro

    TérminoDefinición
    ORMMapeador objeto-relacional: traduce entre objetos del programa y tablas de la base.
    DbContextClase de EF Core que representa una sesión con la base y rastrea cambios.
    DbSet<T>Colección que representa una tabla y sobre la que se escriben consultas LINQ.
    LINQConsultas integradas en el lenguaje C# (Where, Select, OrderBy, GroupBy).
    SaveChangesMétodo que envía a la base todos los cambios pendientes en una transacción.
    API RESTServicio web que expone recursos por URL y se opera con métodos HTTP.
    JSONFormato de texto para intercambiar datos: objetos {}, listas [], texto, números.
    Código de estado HTTPNúmero que indica el resultado de la petición (200, 404, 500…).
    DeserializarConvertir texto JSON en objetos del programa.
    Clave de APITexto secreto que identifica a su aplicación ante un servicio web; no se publica.
    Schema (Mockaroo)Descripción de los campos de los datos de prueba que genera el servicio.
    EnsureCreatedMétodo de EF Core que crea la base y las tablas si no existen; no actualiza una base ya creada.

    Cierre y transferencia del aprendizaje

    Generar un reporte o consultar un servicio en Internet no son solo técnicas: son decisiones sobre la confianza que el usuario puede tener en su programa. Un ORM que evita el SQL repetido, reportes con totales verificables y una importación que valida cada fila y avisa de los errores en lugar de cerrarse pueden convertir el inventario de doña Martha en una herramienta confiable, que se puede probar con cientos de productos sin escribirlos a mano.

    Así como doña Martha pasó del cuaderno a la pantalla y de la memoria a una base de datos, usted completa en este encuentro el camino de AgroStock: la versión 3 reúne interfaz gráfica, base de datos con ORM, reportes y servicio web.

    Conclusiones clave del encuentro

    1. Un ORM mapea clases a tablas: se trabaja con objetos y LINQ, y SaveChanges genera el SQL.
    2. Un reporte útil tiene encabezado, detalle, totales y pie de página; en Excel los totales son fórmulas.
    3. Consumir un servicio web es enviar una petición HTTP y deserializar la respuesta, previendo fallos.
    4. AgroStock v3 reúne lo aprendido: interfaz gráfica, base de datos con ORM, reportes PDF y Excel, y un servicio web para importar productos.

    Transferencia del aprendizaje

    1. Con un ORM, cambiar de SQLite a SQL Server, MySQL o PostgreSQL se reduce, en gran parte, a cambiar el proveedor y la cadena de conexión.
    2. La estructura de un reporte (encabezado, detalle, totales y pie) se repite en facturas, planillas y constancias, sea en PDF o en Excel.
    3. Consumir un servicio web con HttpClient, deserializar la respuesta y prever fallos le servirá con cualquier API que encuentre en su vida profesional.
    «La práctica constante es la clave». Aplíquese a las consultas del encuentro y a AgroStock v3, y estará construyendo una competencia que le acompañará durante toda su carrera profesional.
