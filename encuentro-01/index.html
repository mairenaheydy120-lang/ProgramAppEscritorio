Vivencia

Doña Martha atiende un agroservicio en la salida hacia San Ramón. Anota en un cuaderno cada quintal de fertilizante que entra y sale. Cuando un productor pregunta si hay fórmula 18-46-0, ella revisa varias páginas; a fin de mes suma a mano y casi nunca coincide con lo que hay en bodega.

Preguntas generadoras (responde en tu cuaderno y comenta con tu pareja):

  1. ¿Qué información anota doña Martha de cada producto? Haz una lista de campos.
  2. Si tuvieras que diseñar la pantalla para registrar un producto, ¿qué control usarías para cada campo: cuadro de texto, lista desplegable, número, fecha?
  3. ¿Qué debería pasar cuando ella pulsa «Guardar» y olvidó escribir el precio?
  4. ¿Qué programas de escritorio conoces en tu comunidad (facturación, planillas, control de ventas)? ¿Qué tienen en común sus ventanas?
Lo que esperamos aprender: al terminar este módulo podrás construir una aplicación de escritorio con ventanas, controles, eventos, menús y cajas de diálogo, y la aplicarás al caso de doña Martha.

Contenido

1. Estructura de una aplicación de interfaz gráfica

Una aplicación de interfaz gráfica de usuario (GUI) presenta la información en ventanas y responde a lo que el usuario hace con el ratón y el teclado. A diferencia de un programa de consola, que ejecuta instrucciones de arriba hacia abajo, una aplicación GUI es dirigida por eventos: después de mostrar la ventana, espera a que ocurra algo (un clic, una tecla, un temporizador) y ejecuta el código asociado (Ceballos, s. f.; Deitel y Deitel, s. f.).

En .NET, la tecnología Windows Forms permite construir estas aplicaciones con el lenguaje C#. Un proyecto Windows Forms típico contiene:

ArchivoFunción
AgroStock.csprojConfiguración del proyecto: versión de .NET (net8.0-windows), uso de Windows Forms y paquetes NuGet.
Program.csPunto de entrada. El método Main inicializa la aplicación y llama a Application.Run(new FrmPrincipal()).
FrmPrincipal.csClase del formulario que hereda de Form. Aquí se escribe el código de los eventos.
FrmPrincipal.Designer.csCódigo generado por el diseñador visual: crea los controles y asigna sus propiedades en InitializeComponent().
C#
internal static class Program
{
    [STAThread]
    private static void Main()
    {
        ApplicationConfiguration.Initialize(); // estilos visuales y DPI
        Application.Run(new Forms.FrmPrincipal()); // inicia el bucle de mensajes
    }
}

Application.Run inicia el bucle de mensajes: el sistema operativo coloca en una cola cada acción del usuario y la aplicación la convierte en un evento del control correspondiente. El atributo [STAThread] indica que la interfaz se ejecuta en un único hilo (el hilo de la interfaz); lo retomaremos en la Unidad III.

Un formulario es una clase. Por eso aplicamos lo aprendido en Programación Orientada a Objetos: el formulario hereda de Form, sus controles son atributos privados y los manejadores de eventos son métodos.

2. Uso de controles en un formulario

Un control es un componente visual reutilizable. Cada control tiene propiedades (su estado: Text, Enabled, Visible), métodos (acciones: Focus(), Clear()) y eventos (avisos: Click, TextChanged). Elegir el control correcto evita errores de captura.

ControlUso en AgroStockPropiedad/evento clave
LabelEtiquetas de los camposText
TextBoxCódigo y nombre del productoText, MaxLength, PlaceholderText / TextChanged, KeyPress
ComboBoxCategoría (lista cerrada)DropDownStyle = DropDownList, Items / SelectedIndexChanged
NumericUpDownPrecio y existenciaDecimalPlaces, Minimum, Maximum / ValueChanged
DateTimePickerFecha de vencimientoFormat, ShowCheckBox / ValueChanged
ButtonGuardar, CancelarText, DialogResult / Click
DataGridViewLista de productosDataSource, SelectionMode / CellDoubleClick

Para que la ventana se vea bien en cualquier tamaño de pantalla se usan las propiedades Dock (acoplar a un borde o llenar) y Anchor (mantener la distancia a los bordes), y contenedores como TableLayoutPanel (cuadrícula de filas y columnas) y FlowLayoutPanel (elementos uno tras otro).

C#
var tabla = new TableLayoutPanel { Dock = DockStyle.Fill, ColumnCount = 2 };
tabla.ColumnStyles.Add(new ColumnStyle(SizeType.Absolute, 120)); // etiquetas
tabla.ColumnStyles.Add(new ColumnStyle(SizeType.Percent, 100));  // controles
tabla.Controls.Add(new Label { Text = "&Nombre:", AutoSize = true });
tabla.Controls.Add(txtNombre);
Convención de nombres: prefijo del tipo + propósito (txtNombre, cboCategoria, nudPrecio, btnGuardar, dgvProductos). Evita dejar button1 o textBox2: el código se vuelve ilegible.
3. Manejo de eventos

Un evento es un aviso que un objeto (el emisor) envía cuando algo ocurre. Otros objetos se suscriben con el operador += indicando el método que debe ejecutarse (el manejador). Todo manejador recibe dos parámetros: sender (quién generó el evento) y e (datos del evento, de tipo EventArgs o una clase derivada).

C#
// Suscripción (en el constructor o en el diseñador)
btnGuardar.Click += BtnGuardar_Click;
txtCodigo.KeyPress += TxtCodigo_KeyPress;

// Manejador: solo letras, dígitos y guion; convierte a mayúscula
private void TxtCodigo_KeyPress(object? sender, KeyPressEventArgs e)
{
    if (char.IsControl(e.KeyChar)) return;          // permitir Retroceso
    if (!char.IsLetterOrDigit(e.KeyChar) && e.KeyChar != '-')
    {
        e.Handled = true;                            // se descarta la tecla
        return;
    }
    e.KeyChar = char.ToUpperInvariant(e.KeyChar);
}
Evento¿Cuándo ocurre?Ejemplo de uso
LoadAntes de mostrar el formulario por primera vezCargar datos iniciales
ClickAl pulsar un botón o elemento de menúGuardar, eliminar
TextChangedCada vez que cambia el textoBúsqueda mientras se escribe
KeyPress / KeyDownAl pulsar una teclaFiltrar caracteres, atajos (Ctrl+F)
CellDoubleClickDoble clic en una celda del DataGridViewAbrir el producto para editar
FormClosingAntes de cerrar la ventana (se puede cancelar)Confirmar salida
Tick (Timer)Cada intervalo del temporizadorReloj en la barra de estado

La validación de datos se hace en el evento del botón Guardar (o en Validating de cada control). El componente ErrorProvider muestra un icono junto al control con el mensaje de error, sin interrumpir con ventanas emergentes.

C#
private void BtnGuardar_Click(object? sender, EventArgs e)
{
    errores.Clear();
    if (txtNombre.Text.Trim().Length < 3)
    {
        errores.SetError(txtNombre, "Escriba al menos 3 caracteres.");
        return;                        // el diálogo sigue abierto
    }
    Producto.Nombre = txtNombre.Text.Trim();
    DialogResult = DialogResult.OK;    // cierra el formulario modal
}
4. Menús y barras de herramientas

Los menús organizan todas las funciones de la aplicación; las barras de herramientas ofrecen acceso rápido a las más usadas; la barra de estado informa sin interrumpir. En Windows Forms se usan MenuStrip, ToolStrip y StatusStrip, cuyos elementos (ToolStripMenuItem, ToolStripButton, ToolStripStatusLabel) comparten el mismo modelo de eventos.

  • El carácter & antes de una letra crea la tecla de acceso: "&Archivo" se abre con Alt+A.
  • ShortcutKeys asigna un atajo global: Keys.Control | Keys.N para Nuevo.
  • ToolTipText muestra una ayuda al pasar el ratón sobre un botón.
  • ContextMenuStrip crea el menú del clic derecho y se asigna a la propiedad ContextMenuStrip del control.
C#
var archivo = new ToolStripMenuItem("&Archivo");
archivo.DropDownItems.Add(new ToolStripMenuItem("&Nuevo producto", null, (_, _) => Nuevo(), Keys.Control | Keys.N));
archivo.DropDownItems.Add(new ToolStripSeparator());
archivo.DropDownItems.Add(new ToolStripMenuItem("&Salir", null, (_, _) => Close()));
menu.Items.Add(archivo);

var barra = new ToolStrip();
barra.Items.Add(new ToolStripButton("Nuevo", null, (_, _) => Nuevo()) { ToolTipText = "Nuevo (Ctrl+N)" });
Principio de diseño: toda acción de la barra de herramientas debe existir también en el menú. Así el usuario que no usa ratón puede llegar a ella con el teclado (accesibilidad).
5. Cajas de diálogo

Una caja de diálogo es una ventana secundaria que solicita información o confirma una acción. Es modal cuando bloquea la ventana principal hasta que se cierra (ShowDialog) y no modal cuando permite seguir trabajando (Show).

DiálogoPara quéResultado
MessageBox.ShowInformar, advertir, confirmarDialogResult.Yes / No / OK / Cancel
OpenFileDialogElegir un archivo para abrirFileName
SaveFileDialogElegir dónde guardarFileName
FontDialog / ColorDialogElegir fuente o colorFont / Color
Formulario propio con ShowDialogCapturar datos (FrmProducto)DialogResult + propiedades del formulario
C#
var p = new Producto();
using var dlg = new FrmProducto(p);          // using libera la ventana al terminar
if (dlg.ShowDialog(this) == DialogResult.OK)  // modal: espera la respuesta
{
    productos.Add(p);
}

var r = MessageBox.Show(this, $"¿Eliminar «{p.Nombre}»?", "Confirmar",
    MessageBoxButtons.YesNo, MessageBoxIcon.Question, MessageBoxDefaultButton.Button2);
if (r == DialogResult.Yes) productos.Remove(p);

En el formulario propio, AcceptButton hace que Enter equivalga a Guardar y CancelButton que Esc equivalga a Cancelar. El botón Cancelar con DialogResult = Cancel cierra el diálogo automáticamente.

Síntesis

  • Una aplicación GUI es dirigida por eventos: muestra la ventana y reacciona a las acciones del usuario.
  • Cada formulario es una clase; cada control es un objeto con propiedades, métodos y eventos.
  • Elegir el control adecuado (ComboBox, NumericUpDown, DateTimePicker) previene errores de captura.
  • Menús, barras y atajos hacen la aplicación rápida y accesible; los diálogos confirman y capturan datos.
