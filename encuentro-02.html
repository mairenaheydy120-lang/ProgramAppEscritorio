Bienvenido y bienvenida al segundo encuentro del componente Programación de Aplicaciones de Escritorio. Fundamentación científica · Unidad II

Acceso a bases de datos

1. Introducción a la programación con bases de datos

Una base de datos relacional organiza la información en tablas formadas por filas (registros) y columnas (campos). Cada tabla tiene una clave primaria (PK) que identifica cada fila, y las relaciones entre tablas se expresan con claves foráneas (FK). El sistema gestor (SGBD) garantiza la integridad de los datos mediante restricciones.

En este curso usamos SQLite: un motor relacional que guarda toda la base en un único archivo (agrostock.db) y no requiere instalar un servidor, lo que lo hace ideal para aplicaciones de escritorio. Los conceptos y el código son equivalentes para MySQL o SQL Server: solo cambia el proveedor (MySqlConnection, SqlConnection).

TablaCampos principalesRelación
categoriasid (PK), nombre (UNIQUE)Una categoría tiene muchos productos
productosid (PK), codigo (UNIQUE), nombre, categoria_id (FK), precio (CHECK > 0), existencia (CHECK ≥ 0), vencimientoPertenece a una categoría
movimientosid (PK), producto_id (FK), tipo (ENTRADA/SALIDA), cantidad, fechaMuchos movimientos por producto

La aplicación no habla directamente con el archivo: usa un proveedor ADO.NET (Microsoft.Data.Sqlite) que traduce las llamadas de C# en instrucciones para el motor.

2. El lenguaje SQL

SQL (Structured Query Language) es el lenguaje estándar de las bases relacionales. Se divide en DDL (definición: CREATE, ALTER, DROP) y DML (manipulación: INSERT, SELECT, UPDATE, DELETE). Las restricciones se declaran al crear la tabla.

CREATE TABLE productos (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,   -- clave primaria: identifica cada fila
    codigo       TEXT NOT NULL UNIQUE,                -- obligatorio y sin repetirse
    nombre       TEXT NOT NULL,
    categoria_id INTEGER NOT NULL REFERENCES categorias(id),  -- clave foránea: debe existir esa categoría
    precio       REAL NOT NULL CHECK (precio > 0),    -- CHECK: regla que cada fila debe cumplir
    existencia   INTEGER NOT NULL DEFAULT 0 CHECK (existencia >= 0),
    vencimiento  TEXT NULL                            -- yyyy-MM-dd; NULL si el producto no vence
);
Operación CRUDSentencia SQLEjemplo
CreateINSERTINSERT INTO productos (codigo, nombre, categoria_id, precio) VALUES ('FER-004','Sulfato',1,980);
ReadSELECTSELECT codigo, nombre FROM productos WHERE existencia < 10 ORDER BY nombre;
UpdateUPDATEUPDATE productos SET precio = precio * 1.05 WHERE categoria_id = 1;
DeleteDELETEDELETE FROM productos WHERE codigo = 'HER-005';
-- JOIN: nombre de la categoría junto al producto (une las tablas por la clave foránea)
SELECT p.codigo, p.nombre, c.nombre AS categoria
FROM productos p JOIN categorias c ON c.id = p.categoria_id;

-- GROUP BY: valor del inventario por categoría (agrupa y suma)
SELECT c.nombre, COUNT(*) AS productos, SUM(p.precio * p.existencia) AS valor
FROM productos p JOIN categorias c ON c.id = p.categoria_id
GROUP BY c.nombre ORDER BY valor DESC;
Cuidado: un UPDATE o DELETE sin WHERE afecta a todas las filas de la tabla. Escriba primero el SELECT con el mismo WHERE para ver qué filas cambiarán.

Ejemplo aplicado — AgroStock: «¿qué productos tienen existencia menor que 10?» y «¿cuánto vale mi inventario?», las preguntas que doña Martha respondía sumando a mano, ahora son una consulta SELECT.

3. Clases para la gestión de bases de datos

ADO.NET define un conjunto de clases comunes a todos los proveedores. Con Microsoft.Data.Sqlite se llaman así:

ClaseResponsabilidad
SqliteConnectionAbre y cierra la conexión con el archivo de la base (cadena de conexión).
SqliteCommandContiene la sentencia SQL y sus parámetros. ExecuteReader (SELECT), ExecuteNonQuery (INSERT/UPDATE/DELETE), ExecuteScalar (un valor).
SqliteDataReaderRecorre las filas del resultado, hacia adelante y de solo lectura.
SqliteTransactionAgrupa varias operaciones: se confirman todas (Commit) o ninguna (Rollback).
public List<Producto> Listar(string filtro = "")
{
    using var cn = Db.Abrir();          // using: la conexión se cierra SIEMPRE, aunque ocurra un error
    using var cmd = cn.CreateCommand();
    cmd.CommandText = SelectBase + " WHERE p.nombre LIKE $f OR p.codigo LIKE $f ORDER BY p.nombre";
    cmd.Parameters.AddWithValue("$f", $"%{filtro}%");   // el valor viaja aparte: nunca se concatena

    var lista = new List<Producto>();
    using var rd = cmd.ExecuteReader(); // recorre las filas una por una
    while (rd.Read())
        lista.Add(new Producto { Id = rd.GetInt32(0), Codigo = rd.GetString(1), Nombre = rd.GetString(2) /* ... */ });
    return lista;
}

Inyección SQL. Si se concatena lo que escribe el usuario, alguien puede alterar la consulta. Los parámetros envían el valor por separado y el motor nunca lo interpreta como código SQL.

// MAL: si el usuario escribe  ' OR 1=1 --  la condición siempre es verdadera y se muestran TODOS los productos
cmd.CommandText = "SELECT * FROM productos WHERE nombre = '" + txtBuscar.Text + "'";

// BIEN: $f es un parámetro; el texto escrito se compara tal cual, aunque tenga comillas o guiones
cmd.CommandText = "SELECT * FROM productos WHERE nombre = $f";
cmd.Parameters.AddWithValue("$f", txtBuscar.Text);

Patrón Repositorio. Todo el SQL vive en una clase (ProductoRepository) y los formularios solo llaman a sus métodos (Listar, Insertar, Actualizar, Eliminar). Así la interfaz no depende del motor de base de datos.

Ejemplo aplicado — AgroStock: si un cliente busca «O'Brien», o alguien escribe comillas en el cuadro de búsqueda, AgroStock no se rompe ni expone datos, porque la búsqueda usa un parámetro.

4. Controles de acceso a bases de datos y CRUD

Windows Forms enlaza datos a controles mediante la propiedad DataSource. BindingSource actúa como intermediario: conoce el elemento actual (Current), permite filtrar y notifica cambios.

fuente.DataSource = repo.Listar(txtBuscar.Text);   // BindingSource: intermediario
dgv.DataSource = fuente;                           // DataGridView muestra la lista

cboCategoria.DataSource = repo.Categorias();
cboCategoria.DisplayMember = "Nombre";   // lo que el usuario VE
cboCategoria.ValueMember = "Id";         // lo que el programa GUARDA (la clave foránea, en SelectedValue)

private void Nuevo()
{
    var p = new Producto();
    using var dlg = new FrmProducto(p, repo.Categorias());
    if (dlg.ShowDialog(this) != DialogResult.OK) return;
    try { repo.Insertar(p); Cargar(); }
    // 2067 = SQLITE_CONSTRAINT_UNIQUE: la base rechazó el código repetido; se avisa sin cerrar el programa
    catch (SqliteException ex) when (ex.SqliteExtendedErrorCode == 2067)
    {
        MessageBox.Show(this, $"El código {p.Codigo} ya existe.", "No se guardó");
    }
}

Transacciones. Una entrada o salida de mercadería cambia dos tablas: agrega el movimiento y modifica la existencia. Si una falla, la otra no debe quedar guardada.

using var tx = cn.BeginTransaction();   // desde aquí nada es definitivo
// ... INSERT en movimientos y UPDATE de productos.existencia, ambos con cmd.Transaction = tx ...
tx.Commit();   // todo salió bien: se confirman las dos operaciones
// Si ocurre una excepción antes del Commit (por ejemplo CHECK existencia >= 0), al liberar "tx" se hace Rollback solo.

Ejemplo aplicado — AgroStock: si doña Martha registra una SALIDA de 50 sacos y solo hay 24, la base rechaza el movimiento, se revierte la transacción y la existencia nunca queda negativa.

Programación concurrente

5. Introducción a la programación concurrente

Un proceso es un programa en ejecución con su propia memoria. Un hilo (thread) es una secuencia de instrucciones dentro de un proceso; un proceso puede tener varios hilos que comparten la misma memoria. La programación concurrente consiste en organizar varias tareas que progresan al mismo tiempo, ya sea en paralelo (varios núcleos) o intercalándose.

Las aplicaciones Windows Forms tienen un único hilo de interfaz (UI thread) que procesa los eventos y dibuja la ventana —el [STAThread] que vio en el Encuentro 1—. Si un manejador de eventos tarda 30 segundos, durante ese tiempo la ventana no puede redibujarse ni responder: Windows la marca como «No responde». La solución es mover el trabajo pesado a otro hilo y devolver solo los resultados a la interfaz.

Ejemplo aplicado — AgroStock: cargar 500 productos en el hilo de la interfaz deja la ventana blanca durante casi un minuto; en un hilo de trabajo, doña Martha puede seguir moviendo la ventana y viendo el avance.

6. Clases para trabajar con hilos

Clase / técnicaCuándo usarla
ThreadControl directo de un hilo (nombre, prioridad, IsBackground). Útil para aprender los estados; costoso crear muchos.
ThreadPoolConjunto de hilos reutilizables administrado por .NET.
Task + Task.RunOpción recomendada: ejecuta trabajo en el ThreadPool y se puede esperar con await.
async / awaitEspera una tarea sin bloquear el hilo de la interfaz; el código continúa en la UI al terminar.
BackgroundWorkerComponente histórico de Windows Forms (eventos DoWork, ProgressChanged, RunWorkerCompleted).
IProgress<T> / Progress<T>Reporta avance desde el hilo de trabajo; el manejador se ejecuta en el hilo de la UI.
private async void BtnIniciar_Click(object? sender, EventArgs e)   // async void: solo en manejadores de eventos
{
    cts = new CancellationTokenSource();
    var token = cts.Token;
    // Progress<int> se crea en el hilo de la UI: su manejador también corre allí y puede tocar controles
    var progreso = new Progress<int>(pct => barra.Value = pct);
    try
    {
        await Task.Run(() => Importar(ruta, progreso, token));   // el trabajo corre en el ThreadPool
        lblEstado.Text = "Importación terminada";                // después del await se vuelve al hilo de la UI
    }
    catch (OperationCanceledException) { lblEstado.Text = "Cancelada"; }
}

Ejemplo aplicado — AgroStock: FrmImportar usa Task.Run para leer el CSV, IProgress para llenar la barra y await para volver a la ventana sin congelarla.

Estado (ThreadState)SignificadoSe llega con

var hilo = new Thread(() => Thread.Sleep(1500)) { Name = "Trabajador" };
Console.WriteLine(hilo.ThreadState);   // Unstarted
hilo.Start();
Thread.Sleep(200);                     // se da tiempo a que el hilo llegue a su Sleep
Console.WriteLine(hilo.ThreadState);   // WaitSleepJoin

8. Mecanismos de sincronización

Cuando dos hilos modifican el mismo dato sin coordinación ocurre una condición de carrera: la operación contador++ en realidad es leer, sumar y escribir, y los hilos pueden intercalarse perdiendo incrementos.

object candado = new();
lock (candado) { contador++; }                  // sección crítica: un hilo a la vez
Interlocked.Increment(ref contador2);           // operación atómica, sin lock

using var semaforo = new SemaphoreSlim(2);      // máximo 2 tareas simultáneas
await semaforo.WaitAsync();
try { /* descarga */ }
finally { semaforo.Release(); }                 // SIEMPRE devolver el permiso, aunque falle
Regla de oro de Windows Forms: solo el hilo de la interfaz puede tocar los controles. Desde otro hilo se usa IProgress<T>, Control.Invoke o se devuelve el resultado y se asigna después del await. Violar esta regla produce la excepción «Operación no válida a través de subprocesos».

Ejemplo aplicado — AgroStock: el contador de productos insertados y la lista de líneas rechazadas se protegen con Interlocked y lock, para que el total mostrado a doña Martha siempre coincida con lo guardado.

👉 Vea los incrementos perdidos y el límite de tareas en el simulador del paso 7 de la guía.

9. Detención controlada de hilos

Un hilo nunca debe detenerse a la fuerza (Thread.Abort está obsoleto y no funciona en .NET moderno): puede dejar archivos abiertos o datos a medias. La detención controlada es cooperativa: la interfaz solicita la cancelación con CancellationTokenSource.Cancel() y el hilo revisa el token periódicamente, libera recursos y termina.

using var tx = cn.BeginTransaction();
for (int i = 0; i < lineas.Length; i++)
{
    if (token.IsCancellationRequested)            // la tarea revisa el token en un punto seguro
    {
        tx.Rollback();                            // nada queda a medias
        token.ThrowIfCancellationRequested();     // sale de la tarea con OperationCanceledException
    }
    repo.Insertar(Parsear(lineas[i]), cn, tx);
    progreso?.Report((i + 1) * 100 / lineas.Length);
}
tx.Commit();                                      // solo si llegó al final se vuelve definitivo

Ejemplo aplicado — AgroStock: si el hijo de doña Martha pulsa «Cancelar» a la mitad de la importación, la transacción se revierte y la base queda exactamente como estaba, sin 250 productos a medias.

    Glosario del encuentro

    TérminoDefinición
    Clave primaria (PK)Campo que identifica de forma única cada fila de una tabla.
    Clave foránea (FK)Campo que referencia la clave primaria de otra tabla y crea la relación.
    RestricciónRegla de la base de datos (NOT NULL, UNIQUE, CHECK) que protege la integridad de los datos.
    CRUDCreate, Read, Update, Delete: las cuatro operaciones básicas sobre datos.
    ParámetroMarcador (como $f) cuyo valor viaja separado del SQL; evita la inyección.
    Inyección SQLAtaque que altera una consulta concatenando texto malicioso; se evita con parámetros.
    RepositorioClase que concentra todo el SQL de una entidad y oculta el motor a la interfaz.
    TransacciónGrupo de operaciones que se confirman todas (Commit) o ninguna (Rollback).
    HiloSecuencia de ejecución dentro de un proceso; varios hilos comparten memoria.
    Hilo de la interfazÚnico hilo que dibuja la ventana y puede tocar los controles.
    Condición de carreraError que aparece cuando varios hilos modifican un dato sin sincronización.

    Cierre y transferencia del aprendizaje

    Guardar datos y hacer trabajo en segundo plano no son solo técnicas: son decisiones sobre la confianza que el usuario puede tener en su programa. Una base de datos con restricciones, consultas parametrizadas y tareas cancelables pueden convertir el inventario de doña Martha en una herramienta confiable, que resiste apagones, errores de captura y listas de cientos de productos.

    Así como doña Martha pasó del cuaderno a la pantalla, y ahora de la memoria a una base de datos, usted avanza en su camino en la programación de aplicaciones de escritorio: AgroStock v2 es la segunda etapa de una aplicación que completaremos en el próximo encuentro.

    Conclusiones clave del encuentro

    1. Los datos viven en la base, no en la memoria: sobreviven al cierre y a los apagones.
    2. Toda consulta con datos del usuario se parametriza; el SQL vive en el repositorio.
    3. El hilo de la interfaz solo dibuja y responde; el trabajo pesado va a otro hilo o tarea, con progreso por IProgress.
    4. La sincronización (lock, Interlocked, SemaphoreSlim) protege los datos compartidos entre hilos.
    5. La cancelación cooperativa con CancellationToken y una transacción con Rollback detienen una tarea sin dejar datos a medias: así AgroStock v2 reemplaza la lista en memoria de v1.

    Transferencia del aprendizaje

    1. SQL y las restricciones de integridad son los mismos en MySQL, SQL Server o PostgreSQL: solo cambia el proveedor.
    2. El patrón Repositorio y los parámetros le servirán para el ORM que verá en el Encuentro 3.
    3. Cualquier aplicación que consuma un servicio web o genere un reporte pesado necesitará las mismas tareas en segundo plano y cancelación.
    «La práctica constante es la clave». Aplíquese a las consultas del encuentro y a AgroStock v2, y estará construyendo una competencia que le acompañará durante toda su carrera profesional.
